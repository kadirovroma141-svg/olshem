# Архитектура
- `src/core` — математическое ядро без DOM: `geometry.ts` (плоскости, расстояния, углы, сечения, объёмы с учётом вырожденных случаев), `expr.ts` (безопасный парсер, без `eval`), `scene.ts` (формат сцены и безопасная загрузка).
- `src/data` — проверка структуры задач (`validate.ts`), поиск/фильтры (`catalog.ts`), независимый пересчёт эталонных ответов через ядро (`verify.ts`).
- `src/i18n` — JSON-локализация kk/ru/en, резерв на ru, тест полноты ключей.
- `src/storage/db.ts` — IndexedDB: профили, сессии (версии, привязка к профилю), очередь синхронизации с идемпотентными `opId`, миграции схемы.
- `src/ai` — `AIProvider`, локальный поставщик правил, `safeRespond` (проверка схемы, защита от утечки ответа, тайм-аут, ограничитель частоты, резерв).
- `data/` — задачи, решения, правила, каталог ошибок (JSON). Все статусы проверки честные: `pending` / `auto_validated` / `validated`.
- `public/sw.js` — Service Worker: сеть, затем кэш.
## Решения
- Vanilla TypeScript вместо React: 12,9 КБ gzip JS на текущий момент; React добавил бы десятки КБ без пользы на этом этапе.
- Холст 2D с собственной проекцией вместо тяжёлой 3D-библиотеки: подходит для куба и простых построений; для сложных сцен потребуется пересмотр (JSXGraph/three.js) с оценкой лицензии и размера.
## Риски
Нет серверной части и авторизации; схемы лежат в `data/schemas` и проверяются ajv в тестах; нет экспертной проверки математики и переводов.

## Занятие класса
`src/class/session.ts` — чистая логика без UI/сервера. Три уровня данных (материал / индивидуальная сессия / сессия класса) разделены: сводка учителя строится из индивидуальных состояний и не содержит идентификаторов и времени. Для реального использования нужен сервер: аутентификация, проверка прав на каждую запись, хранение, API синхронизации (`syncQueue` уже формирует идемпотентные операции).

## Синхронизация
`syncQueue` на клиенте формирует идемпотентные операции (`opId = profile:task@version`). `server/handler.ts` проверяет токен, берёт профиль только из токена (поле profileId в операции игнорируется), подтверждает повторы без изменений, новую версию делает «головной», а правку той же или более старой версии сохраняет как конфликт — данные не теряются. Разрешение конфликта (выбор версии учеником/учителем) в интерфейсе **не реализовано**.

## Внешний ИИ
Клиент → `ExternalAIProvider` (только с согласием, минимум полей) → `server/aiProxy.ts` (токен, лимит, валидация, промпт с правилами из справочника, вызов модели, проверка схемы и утечки ответа) → ответ. Любая ошибка → `safeRespond` откатывается на `LocalRuleProvider`. Ключ провайдера хранится только в окружении сервера. Это поиск по справочнику правил (простой RAG), а не обучение модели на Olshem.
