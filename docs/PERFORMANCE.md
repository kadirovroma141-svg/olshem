# Производительность: методика и фактические результаты

**Среда измерений:** Node.js в контейнере разработки, без ограничения CPU и сети, IndexedDB эмулируется (`fake-indexeddb`, в памяти), сервер — обработчик в том же процессе. **Это не замеры на слабых устройствах и не реальная сеть.** Они показывают логическую корректность под нагрузкой и порядок величин, но не заменяют проверку на целевых устройствах (бюджетный смартфон, старый ноутбук, школьная панель) с троттлингом CPU и сети.

Воспроизведение: `npx vitest run tests/perf.test.ts` и `npm run measure`.

## Размер загрузки (gzip)
INITIAL (html+css+js referenced from index.html) gzip KB: 24.12; all chunks gzip KB: 43.72
Цель ТЗ: до 500 КБ сжатого JS без необязательных AI-модулей — **выполнена с большим запасом** по размеру (то, что реально нужно загрузить для запуска, около 24 КБ). Части каталога загружаются отдельными чанками после старта.

## Нагрузка: один класс, 35 учеников (в процессе)
| Показатель | Результат |
|---|---|
| Учеников, каждый со своей IndexedDB | 35 |
| Сохранений на ученика | 20 |
| Среднее время одного сохранения | ≈ 4 мс |
| 95-й процентиль синхронизации ученика с сервером | ≈ 63 мс |
| Общее время всего сценария | ≈ 170 мс |
| Общее устройство: 35 профилей в одной БД, по 20 сохранений | ≈ 90 мс |
Проверено: все 35 сессий независимы, на сервере у каждого верная головная версия, перемешивания данных нет, потерь и дублей нет.
Не проверено: 35 реальных браузеров/устройств одновременно, реальный сервер и БД, сеть школы, обновление сводки учителя в реальном времени.

## Локальные операции (Node, 5 000–20 000 повторов)
| Операция | Среднее время |
|---|---|
| Сечение шестиугольной призмы плоскостью | ≈ 0,007 мс |
| Объём многогранника | ≈ 0,009 мс |
| Плоскость по трём точкам | ≈ 0,001 мс |
| Разбор и вычисление выражения ответа | ≈ 0,005 мс |
Цель ТЗ — до 100 мс на целевом слабом устройстве. Запас в Node огромен, но на целевом устройстве эти числа **не измерялись**; основная нагрузка, вероятнее всего, придётся на отрисовку холста и запись в IndexedDB, а не на математику.

## Не измерено
Время открытия интерфейса на слабом устройстве, использование памяти, стабильность при долгой работе, восстановление после потери вкладки, поведение при квотах хранилища.
